EvalForge

Reliability testing and release gates for tool using agents

Live productRead only showcase

A model response can look correct even when the agent chose the wrong tool or changed the wrong state. I built EvalForge to test those actions directly, so a release decision rests on what the agent did rather than on how the answer reads.

Every run records the tool calls, their arguments, the trajectory, the resulting state, and the task outcome. A candidate version is compared against a promoted baseline, and the build fails when a gate breaks.

Engineering principles

Evaluate behavior
For agents, I inspect the actions taken and the state changed, rather than reading the final text and calling it correct.
Prefer deterministic checks
If ground truth can be expressed in code, I write it that way before reaching for another model as a judge.
Keep AI systems ordinary
Authentication, tenancy isolation, idempotency, observability and failure handling still matter once a model is in the loop.
