What the measurements changed

  1. No 60-second promise

    3 of 7 models over 60 s on their largest request

    The proposal was 50 maximum-size forecasts in under a minute. One request took two minutes and one model timed out at five, so the existing limits stayed.

  2. A memory guard that refused safe work

    counted file cache as used → counts only unreclaimable memory

    After a few model loads, admission control began turning away work that would have fit. The kernel’s file cache, left by reading checkpoints, was most of what it saw.

  3. Yug’s cold start

    27.0 s uncached → 7.2 s pinned and cached

    One on-demand checkpoint download failed in testing. Yug now loads one version, verified by hash and cached at deploy time, and the service refuses to start rather than download mid-request.

Note

Independent work on my own benchmark. Small samples, limits stated.

  • Null agents in my benchmark

    I pointed six agents that can’t do anything at my own 20-case benchmark. They passed 8 cases, 40%, close to the 38% Zhu et al. found on τ-bench airline. A reply check that needs a case-specific fact closed all eight, and no real model’s verdict changed.

    8/20 → 0/20 passable · GPT-4o 17/20, unchanged

    Limits A 20-case pilot. The checks were written after reading the replies, so the fix is in-sample.

  • Repeated-trial reliability

    Does every one of k tries succeed? pass^k (Yao et al., τ-bench), estimated per case without bias, with a bootstrap over cases rather than runs.

    gpt-4o-mini: pass^8 = 95%, for $0.134

    Limits No case was flaky, so the next probe needs harder cases.
