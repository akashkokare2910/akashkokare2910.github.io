Featured engineering work

EvalForge·AI Agent Reliability & Evaluation Platform

An agent can return a convincing final answer and still have called the wrong tool, passed the wrong argument, or left the world in the wrong state.

EvalForge evaluates tool selection, tool arguments, execution trajectory and final environment state, compares a candidate against a promoted baseline, and fails the build when a quality gate breaks. It ships a Python SDK, a CLI and a GitHub Action, over a multi-tenant FastAPI and PostgreSQL backend with workspace tenancy, scoped API tokens and encrypted BYOK OpenAI credentials. The product surface is Next.js.

Live product·Public read-only showcase

In one real gpt-4o run, the agent was asked to refund order #9999, which did not exist. It listed the customer's orders, refunded a different order for $89.50, and then reported that #9999 had been refunded successfully. Final-answer scoring would not reveal that. The tool trajectory and the final environment state did.

MCPLint·Behavioral Reliability Testing for MCP Agent Tools

JSON Schema validates a tool call after the model has chosen the tool. MCPLint analyses whether the descriptions and schemas make the right tool distinguishable before selection.

Fifteen deterministic lint rules and a cross-tool ambiguity engine produce an explainable 0 to 100 score with no LLM key required. ContractLab extends it into behavioural contracts, adversarial benchmark generation and mutation testing that checks descriptions actually carry the distinctions they claim. SARIF, HTML and JSON reporters make it gate a pipeline. Published on PyPI, backed by 200+ tests.

How I think about AI engineering

  1. Evaluation is part of the product, not an afterthought. If you cannot tell whether a change helped, you are guessing rather than engineering.
  2. Agent correctness is about actions and state, not just text. The final message is the least reliable evidence of what actually happened.
  3. Deterministic checks should carry as much ground truth as possible before reaching for an LLM judge. A rule that always agrees with itself is worth more than a model that mostly does.
  4. AI systems still need ordinary software engineering. Auth, tenancy isolation, idempotency, observability, failure isolation and CI do not become optional because there is a model in the loop.
